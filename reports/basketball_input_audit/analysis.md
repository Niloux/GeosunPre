# 篮球场：面向 LichtFeld-Studio 的 SfM 数据分析

本次任务应定义为：以图像观测为主要约束，对异步曝光的 L/R 双鱼眼序列重新估计相机位姿与场景结构，形成适合 LichtFeld-Studio 原生鱼眼训练的输入。导航 pose、设备外参和全局 LAS 均属于待验证的先验；L/R 内参以 `.pro` 标定为初值，也需要检查残差与参数稳定性。

本报告完成于 2026-09-22。已检查全部 4,034 张 JPEG 的文件头/EXIF、全部逐图 pose 和两份导航文本、LAS 文件头及均匀抽取的 200,000 条点记录，并浏览 16 张 L/R 和 8 张 M 的缩略图。尚未运行 LoMa、SfM、配准或 3DGS；JPEG 文件头可读不等于全部图像已完整解码验收。

## 2. 数据中的实际证据

### 2.1 L/R 标定

`.pro` 只有 `camera_L` 和 `camera_R`。按用户给定模型：

```text
COLMAP / OpenCV fisheye 参数：fx fy cx cy k1 k2 k3 k4
k4 = .pro.p3
```

| 参数 | L | R |
|---|---:|---:|
| focalLength / pixelSize | 964.7500 px | 966.4375 px |
| k1 | -0.02911172 | -0.03066998 |
| k2 | -0.00399870 | -0.00233379 |
| k3 | 0.00086782 | -0.00006557 |
| k4（来自 p3） | -0.00035317 | -0.00014585 |

焦距换算假定两个长度字段同单位、方形像元、图像未做额外缩放。不能把 `p3` 当针孔模型的切向畸变。鱼眼畸变作用于光轴夹角，多项式为 `theta_d = theta * (1 + k1*theta² + k2*theta⁴ + k3*theta⁶ + k4*theta⁸)`。[OpenCV 模型定义](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)

主点字段的坐标约定仍须验证。如果采用“图像中心为原点、标定 y 轴向上”，候选公式为 `cx=W/2+principalX/pixelSize`、`cy=H/2-principalY/pixelSize`，得到 L `(1516.291875, 2001.706875)`、R `(1488.79, 1990.507500)`。这是待核实的转换候选，不能仅凭数值合理就认定正确。还要统一 OpenCV、LoMa、COLMAP 的像素中心约定，避免半像素系统偏差。[COLMAP 坐标约定](https://colmap.github.io/cameras.html)

### 2.2 时间信息与异步曝光

- L/R 文件名时间间隔的中位数约 0.999 秒。入选序列覆盖约 266.833 秒。
- 同编号 L/R 文件名时间相差 0–1 ms。这只说明导出的时间标签接近；按用户确认，不能据此采用同步曝光模型。
- 入选 L 的 EXIF 曝光时长为 5.049–7.741 ms，中位数 7.208 ms；R 为 3.085–7.741 ms，中位数 7.741 ms。
- 所有图像仅发现 `ExposureTime` EXIF 标签，没有可用焦距、设备型号、曝光起止时刻或滚动快门读出时间。M 文件名间隔约 88–89 ms，但本轮不使用。
- 536 条逐图 pose 的时间均比对应文件名晚 1 ms，与 `.pro` 中 `exposureDelay=0.001` 在数值上吻合。其生成规则仍未证实；导入时不能再未经检查地重复补偿 1 ms。
- `篮球场_pos.txt` 与 `篮球场_pos_ENH.txt` 各有 53,727 行，采样间隔约 5 ms。逐行速度和姿态角完全一致，但前者时间比后者晚 **0.355000–0.357200 秒**，中位数 **0.356150 秒**。

最后一项是必须追踪的数据生成/时间基准问题，不能直接解释为真实相机延迟，更不能通过任意修改图像时间消除。若需要使用导航插值、连续轨迹或 LiDAR 时间分组，必须先弄清这一差异。

逐图 pose 自身给出的相邻相机中心间距中位数约 1.07 m，转角中位数约 5.34°，P95 约 32°、最大约 59°。这些是**先验内部统计**，不能证明真实运动；它们提示转弯段、近景和运动模糊值得优先检查。仅有曝光时长不能确定图像是否模糊，也不能确定滚动快门严重程度。

### 2.3 LAS 与导航的坐标信息

LAS 为 1.2、点格式 3，共 **56,941,990 点**，大小 **1,936,027,887 字节**。文件长度与记录数吻合。存在 GPS time、强度、RGB 字段；抽样中约 99.24% 的点至少一个颜色通道非零。颜色存在不证明图像与几何配准正确。

| 数据 | 坐标量级/范围 |
|---|---|
| CameraPos_C2E / pos.txt | 约 `(-2.27e6, 5.01e6, 3.22e6)`，数值上符合 ECEF 量级 |
| pos_ENH.txt | E 约 499968.51–500005.78；N 约 3371778.23–3371811.62；H 约 32.01–34.06 |
| LAS | X 约 -80.64–55.75；Y 约 -58.76–59.92；Z 约 -6.27–49.24 |

LAS header 的 offsets 为 0，没有 VLR，因而没有携带可直接使用的 CRS 元数据。scale=0.0001 是坐标量化步长，不能作为点云精度证明。LAS 点时间抽样约为 352995.324–353263.936，更接近 `pos.txt` 的时间范围，但这仍不足以证明时空配准。

**坐标表达不同与几何不一致是两个问题。** 先明确各自坐标变换，再评估一组全局刚体/相似变换是否能解释场景；局部地图形变、拼接误差和错误着色不会因改变坐标系而自动消失。

`.pro` 引用了四个原始 `.lid` 文件，但本次输入目录没有这些文件。因此，本轮可以分析全局点云，却不具备直接重做原始 LiDAR 建图的完整输入。

### 2.4 抽样图像对重建的影响

见 [L/R 抽样总览](lr_contact_sheet.jpg)；每列为同编号 L/R，仅用于观察，不能作为同步曝光证据。

- 图像有圆形有效成像区、黑色外圈以及明显边缘色带。外圈和设备遮挡容易产生相机固定的假特征，应作为硬无效区处理。
- 球场地砖、规则接缝、白线和重复建筑窗格很多。重复结构可能产生高置信错误匹配；匹配数量不能替代实体正确性和三维轨迹验证。
- 地面是大面积近共面结构。球场线条之外，需要立柱、建筑立面、篮架等非共面约束，避免只在地面局部拟合良好。
- 天空、植被和潜在动态目标需要单独处理；植被不应一律删除，但摆动枝叶不能被强制解释为静态场景。
- L/R 曝光时长和画面亮度有差别。光度差异与几何错位要分别解决。

建议以 **160° 总视场（光轴半角 80°）** 作为首轮明确记录的有效域候选，后续由边缘残差决定是否调整；它不是本次测出的硬件视场。在当前初值下，该圆域半径约 L 1251.91 px / R 1253.25 px，占矩形面积约 41%。图像质量评分和特征覆盖率必须针对有效区域，不能被黑边面积支配。

## 3. 相机与先验的建模方式

### 3.1 首版：每次曝光一个独立位姿

L 与 R 分别共享各自一组内参，每张图像拥有独立的 6DoF 位姿。即两个标定组、536 次独立曝光，而不是按编号构造 268 个同步双目 frame。

共同安装在刚性设备上，并不意味着 `L_i` 和 `R_i` 可共享同一时刻的设备位姿。若后续引入物理设备模型，正确形式应为：

```text
T_world_from_camera(c, i)
    = T_world_from_rig(t[c,i] + delta[c]) * T_rig_from_camera(c)
```

这里需要可靠的时间定义、连续轨迹及可辨识的延迟/外参。独立位姿是本轮保守的基础模型；连续时间异步 rig 是有证据需求时的扩展。滚动快门是单张图像内部的时间变化，不能被“每张图独立位姿”自动修复。COLMAP 的同步 rig 配置不能直接代替这个模型。[COLMAP rig 说明](https://colmap.github.io/rigs.html)

### 3.2 先验的作用逐级增加

1. 首先将 pose 用于候选配对的辅助排序、时间顺序和最终偏差报告；保留时间邻接与图像检索发现的配对，避免错误先验切断真实连接。
2. 由图像几何完成初始化、注册、三角化与 BA。保留无 pose 残差的视觉基线，避免仅用现有 pose 三角化后就宣称完成了 SfM。
3. 若视觉结果存在可诊断的漂移或弱约束段，再评估带稳健损失和合理不确定度的软先验；接受与否依据独立图像验证，不能依据更贴近输入 pose。
4. L/R 内参先固定在核验后的初值，建立可比较基线；全局轨迹稳定后，再分阶段评估有限的内参优化。共享内参可避免每张图各自扭曲来吸收位姿误差。

如果一项先验与图像一致性冲突，应检查时序、坐标转换、标定和误差模型，而不是一味增大其权重。

## 4. LoMa 如何接入

官方实现由 DaD 检测器、DeDoDe 描述子和 LoMa 匹配器构成，提供独立提取接口以及作者维护的 HLoc 接入代码。它适合作为本项目的前端候选，但当前没有这批鱼眼数据上的实测结果。[LoMa 源码](https://github.com/davnords/LoMa/blob/main/src/loma/loma.py)；[HLoc extractor](https://github.com/davnords/Hierarchical-Localization/blob/master/hloc/extractors/loma.py)；[HLoc matcher](https://github.com/davnords/Hierarchical-Localization/blob/master/hloc/matchers/loma.py)

实现时需要明确以下边界：

- 每张图提取一次，固定 keypoint ID，缓存描述子；不同图像对只产生索引匹配，便于构建跨三帧及以上的轨迹。直接反复调用两图 `match()` demo 不是适合完整 SfM 的数据组织。
- 首轮以 LoMa-B 作为待评估基线；是否需要更大模型、更多特征或更高分辨率，由有效静态区域覆盖与留出误差决定。
- 默认路径的检测长边为 1024，描述子输入为 784×784；默认点数为 2048。对 3000×4000 原图，这些默认值不能直接当作高精度定位保证。应记录真实提取分辨率和恢复到原图坐标的过程；必要时评估更高分辨率、分块或多视图一致的特征定位细化。[检测器](https://github.com/davnords/LoMa/blob/main/src/loma/detector/dad.py)；[描述子](https://github.com/davnords/LoMa/blob/main/src/loma/descriptor/dedode.py)
- 在无效区/天空/动态掩码作用下选择有效关键点，并检查球场与外围建筑的分布。若只在提取后过滤，须防止有效点预算被黑圈或天空提前占满。
- 匹配分数用于筛选候选，不等同于几何置信度或像素定位精度。

几何验证必须遵循鱼眼模型：原图像素反投影为标定射线，估计/验证两视图几何，再用原生鱼眼投影衡量残差。不能照抄 README 对原始鱼眼像素直接调用普通 `findFundamentalMat()` 的 demo；鱼眼原图的极线通常不是直线。[LoMa demo](https://github.com/davnords/LoMa#how-to-use)；[OpenCV fisheye](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)

配对图至少包含同相机时间邻接、跨相机邻近时间、视觉检索回环和先验空间邻近候选。不能只匹配同编号 L/R。536 张图穷举是 143,380 对，首轮更适合构造覆盖可靠的稀疏候选图，并检查 L/R 是否通过真实共视轨迹连接成一个模型。

若原生鱼眼边缘匹配明显不足，可评估多个有重叠的虚拟针孔视图作为特征提取域；匹配需映射回同一次原始曝光并统一关键点，最终 BA 和 LFS 输出仍保持原生鱼眼。虚拟裁剪不能作为具有独立位姿、独立基线的额外物理相机。

## 5. 面向 3DGS 的验收目标

目标是让同一静态表面在不同训练图像中投影到一致的位置，同时保留可用的纹理与颜色。仅报告注册数量、稀疏点数量或训练损失不足以验收。

| 维度 | 要记录的证据 | 不接受的情况 |
|---|---|---|
| 覆盖与连通 | 注册数/536；L/R 连接；时间和空间覆盖；回环 | 两路各自成功但互不连接；缺帧集中在转弯段 |
| 匹配来源 | 原始匹配→几何内点→多视图轨迹→三角化→BA 清理各阶段 | 只给最终匹配数，无法解释近景约束在哪一步消失 |
| 像素定位 | 每相机/每图/场景区域/径向分区的 median、P90、P99 | 总体均值低，但地面、近景或边缘有系统性长尾 |
| 轨迹几何 | 轨迹长度、三角化角、深度条件、跨时间/跨相机一致性 | 大量近重复视图或共面弱约束点制造虚假稳定性 |
| 独立验证 | 不参与 BA 的静态对应与完整轨迹；由部分视图三角化，预测留出视图 | 改善某一图像对，却把误差转移给邻帧/另一相机 |
| 光度与图像质量 | 有效域内清晰度、过曝、动态比例；同表面曝光差 | 用颜色修正掩盖双边缘、错位或严重模糊 |

可将关键静态结构在**实际训练分辨率**下达到约 1 px 级跨视图对齐作为首轮工程目标，同时报告误差尾部与区域分布。最终阈值应结合特征定位不确定度制定，当前不能宣称已满足。训练若缩小 2 倍，训练域 1 px 对应原图 2 px；所有统计必须标明分辨率。

对白线、地砖角点、立柱等建立少量人工核验点。验证时区分“匹配的是同一实体”“像素位置是否精确”“当前几何能否解释它”。不能用当前 E 或当前 pose 拒绝一个已经人工确认的实体对应，也不能把沿长直线的位置不确定性当成高精度角点。

## 6. LAS 与 LichtFeld-Studio 的位置

先得到通过图像验证的 SfM，再评估 SfM 与 LAS 的关系。纯视觉重建存在尺度自由度，因此首次对齐可考虑带外点剔除的 Sim(3)；在独立确认尺度后再固定尺度做 SE(3) 精化。需要用跨区域的平面、立柱、立面和图像边缘验证，不能只依赖平面球场上的 ICP 均值。

若一个变换不能同时解释不同区域，应考虑局部 LiDAR 建图误差、SfM 漂移或时间/标定问题。不要强迫全局 LAS 把已经通过独立图像验证的相机拉偏。LAS 作为高斯初始化、深度/法线约束和最终坐标参考，是三个不同用途，都需要分别验证。

本机 `/home/wuyou/LichtFeld-Studio`（检查时 HEAD `7be9166e`）已静态确认：

- `src/io/formats/colmap.cpp:2745` 将 `OPENCV_FISHEYE` 的四个畸变参数读入 FISHEYE 模型。
- `src/training/rasterization/gsplat/Cameras.cuh:843` 实现 OpenCV 鱼眼角度多项式。
- `src/training/trainer.cpp:5944` 区分 GUT 原生畸变路径和 undistort 路径。

因此建议交付原生 L/R 图像和 `OPENCV_FISHEYE` COLMAP 模型，通过 `gut=true`、`undistort=false` 的明确配置使用原生鱼眼。源码支持已检查；本次没有启动 LFS 或验证训练运行。

交付物应包括：

1. 精确图像清单、原图及其唯一映射，两组共享鱼眼标定、每张图最终独立位姿、可信稀疏点与观测轨迹。
2. 与图像像素坐标完全一致的有效域/动态掩码；SfM 的特征掩码与 LFS 的损失掩码分别保存语义，不能仅把无效区域涂黑当成训练掩码。天空可单独保留语义。
3. 从局部重建坐标到交付坐标的变换记录。以 float64 完成原点/坐标转换，再输出适当局部坐标，避免将百万量级坐标直接送入 float32 训练。
4. 每帧质量、匹配与轨迹统计，以及按 L/R、时间和关键区域组织的可浏览验证结果。
5. 若 LAS 通过配准验收，再加入经过适度降采样、剔除异常点的初始化点云及其变换记录。

LFS 的曝光/外观建模只能处理其模型能够解释的光度变化。相机错位、错误畸变、动态遮挡和模糊需要在各自阶段处理，不能把 3DGS 训练是否收敛当作这些问题已经解决的证据。

## 7. 建议的下一步实验顺序
