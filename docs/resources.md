## 本轮实现

- **观测**：每阶段采样 RSS 并记录 CPU 时间；记录 PyTorch CUDA 分配与保留峰值、结束占用。
  `pipeline_status.json` 的 `resources` 保存指标，`operations` 保存嵌套子操作的包含子调用耗时及起止 RSS。
  父子耗时不能直接累加。RSS 每 0.1 秒采样可能漏掉瞬时峰值，另有进程累计高水位补充；
  CUDA 指标只包含 PyTorch 分配器，不代表整卡显存占用。监测不会为了读指标主动初始化 CUDA。
- **内容哈希复用**：只在一次 `run` 内复用，最多 16,384 项；每次检查设备、inode、文件大小、
  纳秒 mtime/ctime，改变时重读。首次哈希还检查读取前后文件身份，拒绝并发修改。
  无跨运行持久缓存；独立 `check` 重新读内容，线程中的导出校验也重新读内容。
  此优化依赖本地文件系统的正常元数据更新语义，不承诺检测绕过操作系统元数据的底层篡改。
- **评估**：保留逐轨迹的两支持点 LM 拟合，专门实现三维 float64 无界二点有限差分，
  步长和可表示的实际 dx 与锁定 SciPy 相同；迭代预算和容差不变。投影按图像分批执行，
  直接填充列数组，维持冻结查询顺序、输出字段和失败分母。
- **对象寿命**：检查完初始 mapping 后释放其副本；轨迹筛选结束即释放邻接图、观测映射及留出集合，
  避免它们伴随后续 BA 和评估驻留。
- **显存缓存**：默认预算从 512 MiB 提升到 2 GiB，并限制为设备总显存的 1/8；
  `GEOSUNPRE_GPU_FEATURE_CACHE_MIB` 可下调或设为 0。GPU 命中时不再加载 CPU 特征；
  CPU 后备 LRU 从 128 张降到 32 张。记录 GPU 命中、缺失、上传字节和缓存峰值。
  匹配完成后回收无引用对象并释放 CUDA 分配器空闲缓存。

- **紧凑轨迹与堆回收**：用连续整数数组保存候选边，用整数节点和图像位集合完成合并；保持排序、冲突规则和输出顺序。特征、匹配、留出阶段结束时尝试通过 glibc `malloc_trim` 归还空闲堆页，不支持时跳过并记录。

## 针对性验证

- 同一最终模型、196,288 个原始留出查询：新旧查询顺序、支持点有效性、失败数和汇总指标一致。
  批量投影最大误差差异约 `3.31e-12` px；原两支持点求解在 13,471 条轨迹上的位置、支持误差和角度逐元素一致。
- 连续运行的 CPU 对照：优化评估 7.53 秒、参考 13.92 秒。独立进程的评估 RSS 高水位约 434 MiB，
  参考约 620 MiB。这些是单模块测量，不是完整流水线的时间或内存收益。
- 同一调用内前端读取与留出校验：首次 2.77 秒，第二次 0.40 秒。
- 64 对真实 GPU 匹配的索引、分数和缓存 token 与参考逐元素相同。
- 测试覆盖修改后恢复 mtime、原子替换文件、缓存作用域、GPU 缓存延迟加载与淘汰、阶段异常记录。

- 完整 163,575 条轨迹的内容、顺序和冲突统计与参考一致；独立进程诊断峰值 RSS 从约 1.74 GiB 降至 0.51 GiB。
- 54 项测试通过，包含空边、排序冲突、生成器输入和超过 64 张图像的位集合。

内存采用本进程 RSS；显存采用本进程 PyTorch 分配器指标，不使用整卡总量。

第一轮 `work/basketball_resources_20260929_01` 峰值 RSS 约 5.90 GiB。尚未加入紧凑轨迹与 glibc 堆回收。
全部特征、匹配和两套留出集与参考一致，536 张注册、0 无效深度，独立导出校验通过。

第二轮 `work/basketball_resources_20260929_02` 完成。进程峰值 RSS 为 **4.42 GiB**（4,633,360 KiB），
相对已提交参考的 5.93 GiB 降低 **25.5%**，相对本轮第一版的 5.90 GiB 降低 **25.1%**。

以下阶段比较均来自本轮两次运行的相同采样方式；第一版已经包含评估优化、哈希缓存和 GPU 缓存调整，
第二版增加紧凑轨迹表示与空闲堆页回收。因此不能把阶段差异全部归因于某一个改动。

### 显存结论

两版 PyTorch 显存峰值相同：最大 allocated **2.45 GiB**，最大 reserved **4.77 GiB**。
这些峰值分别出现在特征和匹配阶段；**没有证明峰值显存下降**。
匹配结束后，两版均只保留 allocated **24.4 MiB**、reserved **60 MiB**，后续 CPU 阶段维持该水平。
2 GiB 特征缓存用于减少重复上传，实际缓存约 1.58 GiB；536 张各上传一次。
若并行训练需要更多显存，可设置 `GEOSUNPRE_GPU_FEATURE_CACHE_MIB=512`，代价是增加上传；
降低预算后的完整流程尚未单独验证。旧已提交运行没有相同的 CUDA 阶段采样，不能作显存峰值同比。
