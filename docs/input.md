# 输入与相机坐标

```text
INPUT/
  场景.pro
  场景_CameraPos_C2E.txt
  场景_pos.txt
  场景_pos_ENH.txt
  Image/L/**/*.JPG
  Image/R/**/*.JPG
  Image/*.JPG               无 L、R 目录时的平铺原图
  Image/enhanced/**/*.JPG   可选
  ResultOut/场景.las        无 ResultOut 时为 INPUT/场景.las
```

输入目录须且仅有一份 `.pro`（PCC 解算项目），其文件名即场景名：CameraPos、两份导航表和默认 LAS 均按该名称读取，不按目录中其他同类文件推断；`--las` 可显式改选。

仅使用 `.pro` 中 L/R 相机及 CameraPos 有精确同名记录的 JPEG，M 不参与。照片默认只从 `Image/L`、`Image/R`（各自只能放对应镜头）读取原图；两者都不存在时改读 `Image/` 根目录下的平铺原图，不递归子目录；忽略 `Image/enhanced`：enhanced 是逐图不同的非线性增强，原图曝光固定、颜色一致，更适合 3DGS 外观建模。配置 `"enhanced_photos": true` 时另读 `Image/enhanced`，同名时优先使用 enhanced，交付图像名仍按 L/R 原图的相对路径，原图缺失时为 `镜头/文件名`。输入中完全没有原图（`Image/L`、`Image/R` 和平铺的 `Image/` 都没有所用的 JPEG）时，自动改读 `Image/enhanced`，并记入 `photos`，日志给出提示；部分原图缺失仍按上述规则报错。各目录内图像名和各镜头帧号须唯一，Pose 绑定图像在所读目录中都缺失时报错。照片来源随配置冻结并记入 scene.json 的 `photos`，改变须使用新工作目录。所用照片尺寸须等于 `.pro`，EXIF orientation 须为 1。按 GPS 周、文件名时间、镜头和图像名排序；L/R 同帧号本身不表示同步：只有同时具有 L、R 的全部帧号的文件名时间都相差不超过 2 ms 时，才按同步刚性 rig 处理（室内、展厅为同步，生产车间 R 先于 L 约 65 ms，为异步）。

文件名为 `GPS周-秒-毫秒_帧号-L或R.JPG`。CameraPos 每行 11 字段：文件名、设备编号、GPS 周、秒、XYZ、四元数四分量。仅使用位置，四元数不用于视觉初始化；不改写时间戳。

鱼眼参数为 `fx fy cx cy k1 k2 k3 k4`。初值：`fx=fy=focalLength/pixelSize`，`cx=width/2+principalX/pixelSize`，`cy=height/2+principalY/pixelSize`，`k4=p3`。主点偏移与 G203 参考流程采用相同的图像坐标方向；p3 含义尚未独立核对。

左上像素中心为 `(0.5,0.5)`。`theta=atan2(sqrt(X²+Y²),Z)`，径向多项式为 `theta*(1+k1*theta²+k2*theta⁴+k3*theta⁶+k4*theta⁸)`。有效域为完整视场 160°，多项式须单调。L/R 内参各共享一组，每次曝光有独立位姿；同步数据在卷帘 BA 中另以全局 L→R 外参软约束同帧两参考位姿（见 README）。

两视图及 PnP 的 RANSAC 共识按原始鱼眼像素计算；透视归一化坐标仅供最小求解器产生候选。PnP 使用 AP3P 候选、6 px 内点门限及鱼眼位姿精调，不将中心与边缘观测混用同一透视坐标容差。

共享内参标定默认使用全部有效轨迹（`calibration_tracks=all`）；可选的 `stable` 仅使用轨迹长度至少 3、最大视差至少 1°、平均重投影误差不超过 2 px 的可靠点，并在标定后固定内参优化全部有效点。两档均在每次末尾标定前补全已验证匹配中未分配的轨迹，再检查同一组可靠轨迹：每幅已注册图至少 32 个观测和 8 个 8×8 覆盖格子，图像图保持连通，有注册图像的镜头分别至少覆盖三个 20° 角度带（每带 100 个观测）。覆盖不足且仍有补匹配轮数时，交给补匹配处理；进入可用子集收尾后，明确记录并排除可靠支撑不足的曝光，移除其观测后重新检查其余曝光。参考图像、图像图连通性或角度带不足仍明确报错。新增点参与随后的 BA，`all` 的双视图点不计入标定支撑。这些约束不替代独立检查点或厂商标定约定核对。

两份导航表行身份须一致，前五列为 GPS 周、秒、XYZ，时序递增。由成对位置拟合 ECEF→ENH 转换：尺度偏离 1 不超过 0.001、逐行残差不超过 2 cm。CameraPos 位置经该转换形成导航先验：SfM 转入导航坐标系后用于注册门限（0.25 m）和全部 BA（σ=3 cm），LAS 联合优化及卷帘 BA 使用同一先验。

相机按卷帘快门处理：每幅照片以读出中线时刻为参考位姿，沿读出轴坐标 c 的读出比例 `s = (c - N/2)/N`；读出轴为存储图像的行或列，按数据分别求解后择优，两镜头共用。读出转动按照片估计，读出时间按镜头共享并以符号表示读出先后，读出平移为读出时间乘以导航轨迹在 CameraPos 时刻 ±50 ms 的差分速度（经同一 ECEF→ENH 转换）。曝光时间戳只用于取速度，不假设 L/R 同步，也不使用导航姿态。导航须覆盖每个曝光时刻前后，否则明确报错。配置 `"rolling_shutter": false` 时按全局快门处理。

LAS 对齐后默认执行卷帘快门校正和独立稀疏点清理。

相机候选须在强力删点前通过原几何质量及 LAS 残差检查；支撑不足或候选未通过时保留对齐模型，并记录原因。无论相机候选是否通过，稀疏点清理均独立执行，另行验收照片保留率、LAS 支撑轨迹保留率和图像图连通性，不以删点代替相机精度改善。

相机优化的三视图要求不作为初始化点云的最低轨迹长度。稀疏点清理允许双视图点，但仍须通过重投影、至少 1.5° 视差、固定相机下的深度不确定度及 LAS 距离检查；抽样 LAS 判远的点在删除前须按 50 万记录分块复核完整有效 LAS，距离门限不变，不要求点属于平面。SfM 最终标定后还会对已验证匹配分量中未分配的观测单独三角化，保留通过几何过滤的独立轨迹。

LAS 支持未压缩 1.2、点格式 0–3；默认读取 `ResultOut/场景.las`，该文件不存在而 `INPUT/场景.las` 存在时读取后者，其他文件使用 `--las` 选择。排除 withheld 和 class-7 噪声，RGB 支持 uint16 中的 8-bit/16-bit 范围，无 RGB 时灰色 127。

配准继承 `LAS XYZ ≈ ENH 减首个 ENH 位置` 假设，单位按米解释；拟合不能确认绝对 CRS 或独立地理精度。LAS 头部范围（外扩 2 m）包含过半照片的 CameraPos ECEF 位置时，按 ECEF LAS 处理：读取时以导航的同一 ECEF→ENH 转换换到上述局部坐标，头部范围取转换后八个角点的包围盒，各阶段报告的 LAS 元数据记录 `frame: ecef_to_navigation_enh` 及 `frame_from_input` 变换；否则按局部 LAS 原样读取。计算使用局部原点，输出恢复局部 LAS 坐标（局部 LAS 即输入坐标）。

LAS 附色可能存在纹理错位，仅作为交付 PLY 的初始颜色。相机优化、质量验收和点清理只使用 LAS 几何与有效点分类，照片对应来自原始图像，不以 LAS 附色作为相机标定或纹理对齐参照。
