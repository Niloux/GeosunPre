# 生产架构

GeosunPre 只有一条生产流程，入口为 `run / export / check`。配置表达场景选择、资源预算和验收条件，算法配方由所属模块管理。

## 流程

| 环节 | 固定实现及作用 |
| --- | --- |
| 输入 | 原始 L/R 图像和初始鱼眼内参；每次异步曝光独立 frame |
| 掩码 | SegFormer 排除天空和人物；初始标定下的 160° FOV 限制有效域 |
| 特征 | LoMa，检测分辨率 1536、最多 3072 特征；局部和全局共用编号 |
| 匹配 | 时间邻域与全局描述子检索；FlashAttention 和 CUDA Graph |
| 观测 | 几何求解前确定全部有效特征、匹配索引及来源文件 |
| 局部标定 | 自动或指定短片段，四步受限视觉 BA |
| 全局重建 | 鱼眼增量 SfM、固定内参 BA、轨迹筛选和共享内参 BA |
| 视觉定稿 | 受限主点 BA，检查曝光完整性、投影、深度及内参边界 |
| 配准 | 导航位置初始化 Sim3，LAS 多尺度稳健点到面配准 |
| 联合更新 | 固定内参，以图像、位置弱先验及可靠 LAS 表面约束位姿、点和 Sim3 |
| 交付 | 验收并选择结果，完整 LAS 体素降采样，发布 COLMAP 和初始化 PLY |

联合候选未通过图像、LAS 或区域检查时，验收全局配准结果；没有合格结果则停止交付。求解检查与最终交付资格分别判断，最终选择集中在 `pipeline/registration.py::select_delivery`。领域名称见[术语表](../GLOSSARY.md)。

`points3D.bin` 保存 SfM 稀疏点及轨迹，`points3D.ply` 保存 LAS 体素质心和平均 RGB，用于 3DGS 初始化。最终相机和两种点云已处于输入 LAS 的 XYZ 坐标。

## 模块职责

| 路径 | 职责 |
| --- | --- |
| `cli.py`、`run.sh` | 命令入口及一键启动 |
| `config.py`、`scene.py` | 场景配置、输入选择、尺寸与内参检查 |
| `artifacts.py` | 文件元数据、JSON 参数比较和原子发布 |
| `pipeline/runner.py`、`task.py`、`runtime.py` | 固定阶段编排、资源预检、任务参数、锁及状态 |
| `masks.py`、`features.py`、`pipeline/data.py` | 语义掩码、共享特征和匹配缓存 |
| `pipeline/observations.py` | 求解前确定观测来源，首次检查数组形状和索引 |
| `pipeline/calibration.py`、`reconstruction.py`、`finalization.py` | 局部标定、全局 SfM 和视觉定稿 |
| `sfm/`、`native/` | 鱼眼几何、轨迹筛选、受限 BA 及原生 Ceres 约束 |
| `registration/`、`pipeline/registration.py` | LAS 配准、联合求解、交付决策和发布 |
| `initialization.py`、`colmap.py` | LAS 初始化点云、原图交付及独立验包 |

## 掩码与缓存

掩码统一写入 `sfm/masks/`，有效图仅排除天空和人物，原因标签为 0 保留、1 天空、2 人物。特征提取与正式导出叠加初始 FOV。固定设备多边形和底部遮挡规则已删除；没有掩码版本分支或另一路流程。

两个 CPU worker 准备虚拟视图，GPU 顺序推理，另两个 CPU worker 完成后处理、标签和预览。相机采样表只在该次掩码调用中共享。有效图和标签原子替换，stats 最后提交；预览缺失可以只用 CPU 重画。

特征按图像名存于 `features/`，匹配按图像对存于 `matches/`。缓存中保存提取和匹配参数，复用时直接比较；输入和已完成阶段使用文件大小及修改时间检查变化。运行环境记录包版本，源码修改不锁死续跑。算法或输入改变后使用新工作目录，避免混用旧阶段。

`load_frontend` 提供按需读取的几何数组，局部标定只读取选定片段，完成模型检查和导出不物化全场数组。`database_and_seed` 一次发布数据库、种子及完成记录，COLMAP 在临时数据库副本上运行。完整阶段原子发布，中断结果归档后重建。

## 检查与测量

维护采用静态检查、定向编译和必要的实际阶段运行，不维护单元测试或回归测试脚本。运行中的模型健康、拟合误差、LAS 支持和交付检查属于生产行为。

文件元数据用于续跑变化检查；接收方验包检查文件大小、模型引用、图像/掩码尺寸、有限参数及 PLY 格式和点数。这些检查不证明逐字节相等、独立绝对精度或下游渲染效果。

性能记录只保留场景、配置、完整进程耗时、资源指标和结果诊断。峰值与阶段结束占用分别报告；缓存复用与新任务计时分别记录。2026-10-08 的[篮球场历史运行](benchmarks/basketball_architecture_20261008.md)早于当前掩码与续跑调整，不能当作当前实现的性能或重建质量结论。
