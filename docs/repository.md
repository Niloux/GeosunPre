# 仓库管理

一键入口为根目录的 `run.sh`，正式命令为 `run / export / check`，唯一正式篮球场配置为
[`configs/basketball.toml`](../configs/basketball.toml)。新运行默认 production + local + flash。
完整使用说明从 [首页](../README.md) 进入，各专题见 [文档索引](README.md)。

## 目录职责

| 路径 | 用途与管理方式 |
| --- | --- |
| `run.sh` | 复用本地权重，离线启动或继续冻结任务；参数透传给 `run` |
| `src/geosunpre/` | 正式 Python 实现；入口不依赖本地实验脚本 |
| `native/` | 必需的原生扩展源码、构建说明、Ceres 接口与许可证 |
| `configs/` | 正式场景配置 |
| `tests/` | 数值、缓存、配置兼容、阶段身份、恢复保护与交付契约检查 |
| `docs/` | 当前使用说明、契约与明确标注的历史记录 |
| `docs/benchmarks/` | 小型验证摘要、运行身份及原记录哈希 |
| `input/` | 原始数据，Git 忽略 |
| `work/` | 重建产物、实验脚本、完整日志与原始证据，Git 忽略 |
| `.cache/` | 模型权重与本地缓存，Git 忽略 |
| `.codegraph/` | 本机代码索引，Git 忽略 |
| `.venv/`、`build/`、`dist/`、`*.egg-info`、`*.so` | 本机环境及构建产物，Git 忽略 |

工作目录内包含绝对路径与冻结身份，保留其原位置。需要搬迁交付时使用复制模式的
`WORK/colmap/`，具体内容见 [交付契约](colmap_contract.md)。

## 正式默认与研发边界

| 内容 | 生产模式 | 验证模式 |
| --- | --- | --- |
| 局部视觉标定 | 默认保留 | 默认保留，可显式做 input 消融 |
| 观测来源 | 冻结全量观测身份 | 几何拟合前冻结留出协议 |
| 留出划分、预测评估、共同查询与 bootstrap | 不执行 | 执行 |
| 深度、单调性、覆盖与完整注册检查 | 执行 | 执行 |
| 导出与独立交付校验 | 执行 | 执行 |

两种模式均沿用默认 FlashAttention、CUDA Graph、特征缓存、CPU 并行处理、
原生深度约束 BA、运行内哈希复用和阶段内存回收。
留出轨迹与评估数组化仅服务验证模式。诊断路径、缓存预算及历史采用依据见
[性能记录](performance.md) 和 [资源记录](resources.md)。

## 冻结配置与续跑

| 冻结配置版本 | 匹配后端 | 标定模式 | 流程模式 |
| --- | --- | --- | --- |
| 1 | 未写字段时 math，显式值保留 | local | validation |
| 2 | 使用已保存值 | local | validation |
| 3 | 使用已保存值 | 使用已保存值 | validation |
| 4 | 使用已保存值 | 使用已保存值 | 使用已保存值 |

新目录写入版本 4。保存相同配置不改写旧文件，避免改变已有下游身份。
旧目录续跑省略 `--config`；切换模式、输入或场景配置时使用新工作目录。
Flash 与 math 的匹配缓存身份独立，生产与验证的观测协议互斥。

`pipeline_task.json` 冻结数值源码、依赖、后端和交付选项。仅资源预检与任务身份管理
模块的变更允许记录审计后继续；原任务文件保持不变。具体规则见
[运行与恢复](engineering_structure.md#运行与恢复)。

## 验证证据管理

启动、缓存复用及导出恢复验证，与生产冷启动、历史性能优化、资源优化及局部标定消融分别记录，见
[验证摘要索引](benchmarks/README.md)。摘要中的哈希对应当次运行快照，
不要求历史源码哈希与后续版本相同；追溯运行时应结合冻结配置和原始记录。

自动化测试、交付完整性校验、拟合诊断、留出预测评估和下游应用质量是不同证据。
当前完整生产运行已通过交付与几何健康检查；其拟合残差不能作为独立精度结论。
原始数据、权重、完整日志和重建结果保留在本地，不随源码包发布。
